# FURNETURE_BOT

Telegram-бот-каталог мебели: покупатель смотрит товары с фотографиями,
фильтрует каталог и оставляет заявку; администратор наполняет каталог и
разбирает заявки в панели `/admin`.

## Возможности

### Покупатель

- Главное меню — команда `/start`; категории грузятся из базы.
- Категории: спальная, кухонная и мягкая мебель, столы и стулья,
  тумбы и комоды, матрасы, кровати, шкафы.
- Фильтры динамические: спальная/мягкая мебель и столы со стульями — по
  странам производства, кухонная мебель — по типам (`Прямая`, `Угловая`);
  варианты берутся из реальных значений в базе.
- Список товаров разбит на страницы по 5 штук, перед ним показывается
  количество найденного; страница и фильтр сохраняются при возврате из карточки.
- Карточка товара: фотографии альбомом, категория, название, описание, тип,
  страна, цена, дата добавления, контакты WhatsApp/Telegram и Instagram.
- Оформление заявки FSM-диалогом: имя → телефон → подтверждение; телефон
  нормализуется в E.164, нераспознанный номер — повторный ввод.
- На каждом уровне есть возврат назад или в главное меню.

### Администратор

- Панель по команде `/admin`; доступ — админы из `.env` (`ADMIN_ID`) или
  пользователи с флагом `is_admin` в базе.
- Категории: добавление и удаление (удаление уносит товары категории).
- Товары: пошаговое добавление (название, описание, категория, тип кухни или
  страна, контакты WhatsApp/Telegram, цена, фото) и удаление из постраничного
  списка с подтверждением.
- Подкатегории кухни: просмотр со счётчиками товаров, снятие метки
  (товары остаются в каталоге).
- Заявки: постраничный список (новые сверху), карточка с именем, телефоном,
  username покупателя и сменой статуса (новая → в работе → выполнена /
  отменена), статистика-снимок по статусам, экспорт всех заявок в CSV
  («;», UTF-8 с BOM — открывается в Excel/Google Sheets).
- Уведомления: при подтверждении заявки админам приходит карточка заказа;
  при смене статуса покупателю — короткое сообщение («в работе» / «выполнена» /
  «отменена»); заблокировавший бота покупатель просто не получает его.

## Структура проекта

```text
main.py                          запуск бота, сборка диспетчера из роутеров
settings/config.py               загрузка BOT_TOKEN/ADMIN_ID из .env
handlers/
  backend/user/router.py         каталог покупателя (меню, фильтры, карточка)
  backend/user/views.py          формирование сообщений каталога
  backend/user/texts.py          тексты карточек и константа Instagram
  backend/user/formatters.py     форматирование цены и дат
  backend/order.py               FSM-заявка и уведомление админов
  admin/__init__.py              сборка админ-роутера + middleware доступа
  admin/access.py                шов авторизации (ADMIN_ID / is_admin)
  admin/router.py                меню панели и приветствие
  admin/categories.py            потоки категорий
  admin/furniture.py             мастер добавления товара
  admin/furniture_delete.py      удаление товара
  admin/subcategories.py         подкатегории кухни
  admin/orders.py                раздел «Заявки»: список, статусы, статистика, CSV
keyboard/user_keyboards.py       inline-клавиатуры каталога, конфиг категорий
keyboard/admin_keyboards.py      inline-клавиатуры панели
keyboard/keyboard_builder.py     построитель inline-клавиатур
keyboard/button_templates.py     шаблоны кнопок
database/models.py               модели SQLAlchemy
database/crud_catalog.py         CRUD: категории, товары, подкатегории, пользователи
database/crud_orders.py          CRUD заявок (списки, статусы, экспорт)
database/crud.py                 фасад-реэкспорт обоих CRUD
database/engine.py               асинхронный движок SQLite
alembic/                         миграции (актуальная голова: e9f4b8c2d6a7)
states/states.py                 состояния FSM каталога и админ-панели
utils/phone.py                   нормализация телефонов в E.164
docs/adr/0001-phone-normalization.md   правила работы с номерами
tests/                           unittest (+ helpers.py — общие заглушки)
```

Роутеры включаются в один Dispatcher в порядке: админ-панель → каталог
пользователя → оформление заявки. Callback_data админки всегда с префиксом
`adm:` и не пересекается с навигацией каталога.

## Стек

- Python 3.12+
- aiogram 3 — бот-фреймворк (long polling, FSM на контексте)
- SQLAlchemy 2 (async) + aiosqlite — ORM и доступ к SQLite без блокировок
- Alembic — миграции схемы
- phonenumbers — парсинг и нормализация телефонов
- python-dotenv — конфигурация через `.env`
- unittest — тесты (stdlib, без pytest); ruff — линтер

## Чего не хватает

- Поиск по каталогу; цены нет в списках (только в карточке).
- Редактирование товара и категории — только добавление и удаление;
  отдельное фото нельзя заменить или удалить.
- Статистика заявок — снимок текущих статусов, истории переходов в схеме нет.
- Нет рассылки по пользователям и блокировки спамеров.
- Только long polling — webhook отсутствует.
- Нет CI (ruff + unittest в GitHub Actions), Dockerfile и стратегии бэкапа SQLite.

## Инструкция

### Установка и запуск

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env             # затем заполните:
# BOT_TOKEN=токен_бота
# ADMIN_ID=ваш_telegram_id       # можно несколько через запятую

./venv/bin/alembic upgrade head  # создать схему и сид категорий
./venv/bin/python main.py        # запуск (long polling)
```

Один процесс — один токен: пользовательская часть, панель и заявки работают
внутри одного бота, второй процесс с polling конфликтует с первым.

### Как стать администратором

Либо укажите свой `telegram_id` в `ADMIN_ID` в `.env`, либо поставьте флаг
в базе:

```sql
UPDATE users SET is_admin = 1 WHERE telegram_id = <ваш_telegram_id>;
```

### Данные каталога

- Товар живёт в таблице `furniture`: `name`, `description`, `category_name`,
  `category_id`, опционально `country` (`Россия`/`Турция`), `subcategory`
  (для кухонной мебели), `whatsapp_contact`, `telegram_contact`, `price`.
- Меню фильтров строится из уникальных значений `country`/`subcategory`,
  поэтому новая страна или тип, введённые при добавлении товара, появляются
  в фильтрах сами; для пустой базы гарантированы `Россия`/`Турция` и
  `Прямая`/`Угловая`.
- Фотографии хранятся в `furniture_photos` по Telegram `file_id`.
- Стандартные категории добавляет миграция `9c3e2a1b7d4f`.

### База данных и миграции

Файл базы — `database/database.db`. После изменения моделей:

```bash
alembic revision --autogenerate -m "Описание изменения"
alembic upgrade head
```

Уже применённые миграции не редактируются — новая схема оформляется новой
ревизией. Цепочка: `9c3e2a1b7d4f` (сид категорий) → `f8b2d4c6a9e1` (контакты
товара) → `c4d9e7f2a8b3` (имя/телефон покупателя и таблица `orders`) →
`e9f4b8c2d6a7` (цена товара).
