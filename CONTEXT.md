# Контекст предметной области

Глоссарий терминов мебельного бота. Без деталей реализации.

## Заявка

### Покупатель
Человек, оформивший заявку на товар через бота. Не совпадает с пользователем
Telegram: у него могут быть пустые профильные имя/username, поэтому контакт
для связи собирается формой отдельно.

### Телефон покупателя
Единственный надёжный канал связи с покупателем для подтверждения заявки.
Вводится покупателем в свободной форме; принимаются номера любых стран,
никакой одной страны по умолчанию не предполагается.

### Контакт товара
Телефон WhatsApp и Telegram-адрес, которые администратор указывает товару
для прямой связи покупателя с магазином. Телефонная часть контакта
подчиняется тем же правилам нормализации, что и телефон покупателя;
Telegram-адрес телефоном не является и не проверяется как телефон.

### Международный формат
Канонический способ записи телефона: плюс, код страны, полный номер
(например `+79001234567`). Целевое состояние данных: любой принятый телефон
хранится в международном формате.

### Локальный формат
Запись номера без явного кода страны: с транковым префиксом (`8900…` в России,
`0…` во многих странах) или вовсе без него (`900…`). Локальная запись сама по
себе не определяет страну — она интерпретируется через страну по умолчанию.
Покупатель из другой страны обязан использовать международный формат с `+`.

### Страна по умолчанию
Россия (регион RU). Применяется только к номерам без `+`: локальную запись
невозможно интерпретировать без контекста, а текущий бизнес-контекст делает
Россию ожидаемым регионом. Это умолчание парсинга, а не утверждение о том,
что бот ориентирован только на Россию.

### Повторный ввод
Единственная реакция на нераспознанный телефон: сообщение об ошибке с
подсказкой указать код страны через `+` и просьбой ввести номер снова.
Заявка не отклоняется, отдельный диалог уточнения страны не заводится,
FSM остаётся в том же состоянии.

### Статус заявки
Жизненное состояние заявки. Ровно один на заявку; история переходов
не ведётся — хранится только текущий статус. Канонические русские метки
(словарь бота, единый для карточек, кнопок и выгрузок):
Новая / В работе / Выполнена / Отменена. В файлах метки пишутся без эмодзи.

### Уведомление покупателя
Одностороннее сообщение от бота покупателю о смене статуса его заявки;
ответ не ожидается и не обрабатывается. Покупатель узнаёт о переходе
в статусы «В работе», «Выполнена» и «Отменена»; установка того же статуса
и возврат в «Новая» проходят молча. Сообщение — одна строка: номер заявки,
товар, новый статус. Недоставляемое сообщение (покупатель заблокировал бота)
не считается ошибкой и никакой реакции не требует.

### Экспорт заявок
Полная выгрузка всех заявок на момент нажатия в один файл CSV для работы
вне системы: открыть в Excel или Google Sheets, отфильтровать, передать
другому человеку. Без фильтров по статусу и периоду — отбор админ делает
сам уже в таблице. Телефон покупателя в файле — в международном формате.
Если заявок нет, вместо файла приходит сообщение об этом.

### Статистика заявок
Снимок текущего состояния: сколько заявок сейчас находится в каждом из
статусов, плюс общий счётчик. Это фотография «сейчас», а не динамика за
период — данных о моментах смены статуса в системе нет, поэтому временн́ые
разрезы не показываются и не обещаются.

## Оплата

### Оплата заявки
Факт получения магазином полной суммы за товар по заявке. Система сама денег
не видит: факт подтверждает администратор, сверяясь с банком вне системы.
Существует независимо от статуса исполнения — оплаченной может быть и
отменённая заявка. Подтверждение обратимо тем же действием (ошибка нажатия,
возврат средств); сам возврат денег происходит вне системы.

### Претензия об оплате
Утверждение покупателя, что он оплатил заявку. Фактом оплаты не является:
только обращение к администратору, который проверяет банк вручную. Хранится,
пока оплата не подтверждена; повторная претензия по той же заявке ничего
не меняет.

### Цена товара
Обязательная характеристика товара: стоимость в рублях целым числом.
Товара без цены не существует. Заявка не фиксирует цену на момент
оформления — покупатель платит текущую цену товара на момент оплаты.

### Реквизиты оплаты
Единый для магазина текст с способом перевода, который покупатель получает
вместе с предложением оплатить. Задаётся конфигурацией магазина, а не через
бота; у магазина один набор реквизитов на все заявки.
